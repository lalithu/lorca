# Lorca v0.5.0 — Persistent memory and sustained execution

Approved for release November 6, 2026. Builds on `v0.4.0-nominal.1` through
[PR #2](https://github.com/lalithu/lorca/pull/2).

## What changed

- Conversation-scoped SQLite FTS5 archives replace full-history RAM scans. Original
  records, native call IDs and attachment metadata remain retrievable after restart.
- Large user inputs become bounded source manifests with exact Unicode chunk
  retrieval. Authority still checks the complete original instruction.
- Numbered context checkpoints preserve essential operational state, complete tool
  exchanges and advisory working notes while older originals remain searchable.
- Length-stopped public answers continue across inference requests with conservative
  echo suppression and matching streamed/final output. Partial tool JSON never runs.
- Completion remains model-owned; permissions, single-use approvals, workspace
  boundaries, cancellation and factual execution status stay enforced by Rust.
- Entire-chat Markdown/JSON exports include archived originals; JSON embeds current
  image attachments. Deletion removes the associated archive and sidecars.
- The read-only model advisor reports hardware and backend allocations without
  loading, replacing or downloading models. Empty llama.cpp catalogs no longer
  override an available Ollama backend during automatic selection.
- Job Apps and its independent tool registry are unchanged.

One existing agent loop remains. `rusqlite` with bundled SQLite is the only new
runtime dependency; there is no separate memory agent, embeddings service or router.

## Install / build

Requires macOS 14+, Rust/Cargo, Xcode or Swift tools, and an already configured
Ollama or llama.cpp model. Job Apps also requires Python 3.

```sh
git fetch origin --tags
git switch main
git pull --ff-only origin main
cargo install --path . --locked --force
LORCA_BUILD_ONLY=1 bash macos/build.sh
open macos/build/lorca.app
```

Quit an older Lorca build before opening this build against the same data. Use
`lorca rebuild` for the existing managed rebuild/restart workflow. Existing chats,
images, settings and Job Apps data are retained. Legacy archive migration is additive;
back up/export chats before downgrading because v0.4 cannot read v0.5-only archives.

## Limits and next work

- Exercise live llama.cpp with an installed model and benchmark representative tasks
  across both Macs before claiming model-independent task quality.
- Recall is lexical FTS5, not semantic embeddings. Available source chunks do not
  prove that the model understood every part of a document.
- Hidden reasoning is not exactly resumable. Echo detection is conservative and
  cannot universally distinguish intentional repetition. Provider/resource failures
  and cancellation may leave partial work.
- Full UI/current-task audit history and explicit exports still grow with history;
  total application memory is not constant. Hardware fit advice remains approximate,
  with no automatic context fitting or model-quality ranking.
- `exec_command` remains restricted to approved Cargo verification operations.
  General shell access and browser automation remain future work.
- System Save dialogs and online model discovery were not click-automated. The
  macOS build uses ad-hoc signing, not Developer ID signing or Apple notarization.
