# Lorca v0.5 — Persistent Agent Runtime: architecture and implementation plan

Status: implementation design plus first incremental recall patch on `feat/v0.5-context-memory-foundation`.
Baseline: `v0.4.0-nominal.1` / `0d3f78166a10fb7f624933fe4144326f4dce9ba7`.
Scope order: **memory/search → context epochs → oversized input → output continuation → tool/semantic cleanup → hardware optimization last**.

## 0. Mission and ownership

**Agent = model + Lorca harness.** The model chooses goals, plans, tools, what is semantically important, when to retrieve or condense working memory, when to ask the user, and when it is finished. Rust owns inference transport, finite resource budgets, durable source records, structured tool dispatch, permission boundaries, execution observations, and lifecycle.

The model's context window is a bound on *one inference*, not on the size of the full conversation/task. Lorca must make bounded execution seamless rather than impose an arbitrary 20-turn or 8K-output task ceiling. Hard failures remain for genuinely impossible resource states, corrupt data, unsafe actions, cancellation, model/backend failure, or unproductive loops; never pretend a limit can be eliminated by more checkpointing.

No required second model, routing prompt, external hosted service, vector database, agent-specific giant framework, or rule-based Rust semantic judge.

All 223 text files were fetched and inspected/scanned; five binary assets (one PDF, three JPEG screenshots, one ICNS) were inventoried but not decoded for architecture analysis. ## 2. Non-negotiable invariants

1. **Originals win.** Archive exact user messages, model public content, structured calls and complete tool observations before projecting/shortening them for inference.
2. **No permission by recollection.** Historical messages, model working notes and archived approvals cannot authorize new actions or be promoted into system instructions.
3. **Never split live tool protocol groups.** An active assistant call and its linked results remain atomic; unconfirmed interrupted calls are repaired in memory as *unexecuted*, never replayed.
4. **No model dependence for memory safety.** Automatic deterministic fitting must work even when the model cannot summarize, call tools, or produce public text.
5. **Model-directed semantics.** The model can curate advisory working notes, initiate compaction and search; Rust does not score whether the final answer satisfies a natural-language objective.
6. **One canonical archive; one active context projection.** No recursive summary chains, proliferating memory agents, or duplicated competing chat histories.
7. **Task- and conversation-scoped retrieval.** Never search another chat, workspace, or system instruction without explicit user action. Result text is untrusted data.
8. **Small local footprint.** Lazy indexing, bounded result pages, no always-on embedding model, no mandatory network service or background daemon.
9. **Crash safety.** An accepted user request and completed tool effects must be durably reconstructible; restart never reexecutes a previously approved command.
10. **No hidden infinite loops.** Resource exhaustion should yield automatic continuation when safe; repeated identical no-progress failures eventually produce an actionable blocker.

## 3. Target module architecture

Preserve the existing public `Agent`, `Registry`, `Inference`, `Context` and `Repository` interfaces as compatibility facades. Put new logic behind **one** memory subsystem rather than distribute it around the agent loop.

```text
src/
  memory.rs or memory/
    mod.rs            // facade: ingest, record, prepare_context, search, get
    archive.rs        // append-only original event/source records + recovery
    index.rs          // FTS5/exact reference index, lazy rebuild
    checkpoint.rs     // epoch boundaries and protected retention
    working.rs        // model-authored notes, references and provenance
    ingest.rs         // oversize input manifests and safe chunk boundaries
    continuation.rs   // segmented public output ledger
  context.rs          // backward-compatible facade / deterministic fallback
  context/budget.rs   // single provider-shared budget object
  tools/agent/        // read-only memory & chunk tools, model notes, compaction request
  agentloop/          // a simple bounded decision -> execution -> observation loop
```

Illustrative interface, not a requirement to use this exact trait:
```rust
trait MemoryRuntime {
    fn append_original(&self, conversation: &str, event: &Event) -> Result<RecordId>;
    fn search(&self, conversation: &str, query: SearchQuery) -> Result<SearchPage>;
    fn read(&self, conversation: &str, id: RecordId, range: Range) -> Result<Excerpt>;
    fn prepare(&self, task: &TaskState, budget: ContextBudget) -> Result<ModelContext>;
    fn checkpoint(&self, task: &TaskState, notes: Option<WorkingNotes>) -> Result<EpochId>;
}
```

`ContextBudget` must always include *actual allocated n_ctx*, the required output reservation, token/schema/media estimates and safety headroom. A model's advertised maximum is not its actual runtime allocation.

## 4. Memory records and persistent archive

### Canonical record

Assign a stable monotonic `conversation_id + sequence` and immutable `record_id` to each accepted input, original generated segment, native tool request, tool result, explicit user correction, and checkpoint. Include `task_id`, `call_id`, `timestamp`, `role`, `kind`, optional file/image references, UTF-8 length, hash, and trust class. Keep tool result bodies in durable source records, not only event snapshots.

**Write-ahead:** before acknowledging a user submission, persist that input; after a tool finishes, persist its result before allowing a new inference. Partial output segments can be batched and flushed at checkpoints without falsely reporting them finished. Persistence failure must be visible and must not silently discard unrecoverable work.

**Storage migration:** do not rewrite existing version-1 conversations in place during the first release. On first access, lazily import/index their `agentHistory`, keep exact backups, and use compatibility read paths. Gradually move large tool-output payloads to append-only sidecars or canonical SQLite records; keep lightweight conversation summaries for the Swift UI. Rebuild indexes from canonical records after interrupted migrations. Use checksums, idempotency keys, and atomic commits.

**Search:** start from the small `HistoryIndex`/tool facade already introduced in this branch. Follow with SQLite FTS5 (one local DB, no embedding runtime) and exact ID/path/role/tool/time filters. Return short snippets plus record IDs; `get_history_record` streams bounded UTF-8 excerpts by offset. Reserve vector/semantic retrieval for evidence that lexical search actually fails important use cases.

**Retention:** model may evict from working memory, never silently delete canonical archives. User-driven deletion and export must include records, attachments, indexes and tombstones. Never index hidden reasoning or system policy as searchable conversation content.

## 5. Stable context epochs and cooperative compaction

### Automatic planner

Before every inference: obtain actual backend allocation; price chat template/tools/media; reserve output and headroom; assemble *system instructions + active user objective/corrections + required in-flight exchange + pinned operational facts + recent turns*. If necessary, freeze a checkpoint and start a fresh epoch. Preserve source references to archived records. The model's system prefix should remain stable for many turns when possible for KV/prefix cache reuse.

Use an entry threshold and a lower post-compaction target (hysteresis) to avoid repeated one-turn truncation. Do not compact halfway through tool generation or after an unacknowledged action. Never recursively paste the previous checkpoint inside the next.

### Model-managed working memory

Expose `update_working_memory` and `compact_context` as discoverable capabilities. The model supplies concise facts, decisions, open questions, source record IDs, and a proposed next step. Model notes are **advisory**, are replaceable, and cannot assert that a tool really executed. Rust validates sizes/references/structure, not semantic quality. A model can ask to inspect older records before submitting new notes.

If the model never calls either tool, automatic deterministic compaction still works. An optional one-shot model-assisted memory turn may be benchmarked later; it is never mandatory on every threshold crossing. Do not force small models into expensive meta-reasoning.

### Compaction transaction

1. Confirm all prior visible tool calls/results are complete or explicitly recorded as interrupted/unexecuted.
2. Persist any unarchived original records.
3. Pin active instructions, objective, corrections and unresolved execution state.
4. Choose recent complete turns and optional model notes to fit the post-compaction target.
5. Create epoch manifest: `epoch_id`, source ranges, pinned record IDs, selected note version, token estimate.
6. Validate budget and correlation, commit the checkpoint, then send the next inference.
7. If model notes are invalid or unavailable, use deterministic safe fallback; do not drop protected content to make the note fit.

Important limitation: when the protected active state itself cannot fit after virtualization, there is a real impossibility and Lorca must ask for guidance or report it transparently.

## 6. Oversized input: automatic input virtualization

Do not put full raw user text into `Submission.task` and hope a larger constant fixes it. Replace the existing 8,000-byte gate in `src/agentloop/runtime.rs` and `src/core/agent_chats.rs` with an ingestion stage **before** task construction.

For each submitted input, persist the exact bytes once; classify its shape (plain prose, document, code, logs, attachment); segment at UTF-8-safe semantic boundaries (headings, paragraphs, lines, code blocks) into bounded chunks; create a manifest containing source ID, count, lengths, headings and retrieval coordinates. Keep a short task envelope and the original instruction pointers in protected context. Let the model call `read_input_chunk` / `search_input` as needed.

For a task requiring whole-document coverage, maintain a deterministic cursor and explicit coverage ledger across checkpoints; *do not assume lexical search of only relevant chunks is exhaustive*. Give the model a way to request the next sequence of chunks and synthesize findings incrementally. For a narrowly targeted question, allow targeted retrieval first. Unbounded raw user material never becomes an inferred higher-priority policy. Attachments may require modality-specific segmentation; do not promise that image/audio processing is available for every model.

Acceptance: 30K-token input on an 8K allocation is accepted, preserved byte-for-byte, inspectable in full, and processed over multiple inference requests without the user manually pasting smaller chunks. Semantic answer quality remains model-dependent.

## 7. Long outputs and reasoning: segmented generation

**Streaming one generation ≠ continuing across generation limits.** In both provider adapters, normalize explicit stop cause: `stop`, `length`, `interrupted_tool_call`, `timeout`, `cancelled`, `unknown`. A text `length` stop may continue automatically; a truncated native tool call must *never* execute.

Implement a per-task `OutputLedger`: sequential segment number, byte/character length, emitted text, known headings/checkpoint, last confirmed public output, source turn and stop reason. Stream each segment to the UI as one logical response. On `length`, persist the partial public segment, assemble an output continuation context (original objective + outline + last bounded tail + source references + explicit nonrepetition instruction), and invoke the same model again. Deduplicate only confidently identical boundary text; never silently rewrite generated user-visible content.

**Reasoning:** private hidden chain-of-thought generally cannot be serialized and resumed. Treat generation-cap exhaustion during reasoning as a fresh inference with the original objective and durable observable state, not fabricated reasoning continuation. Thinking ON/OFF remains model/provider-specific. If repeated fresh continuations make no progress, report an actionable blocker without claiming completion.

Maintain safety watchdogs: per-inference timeouts, overall opt-in user cancellation, consecutive no-progress detection, max single output segment, disk quotas and backpressure. Do not introduce arbitrary global turn/output ceilings for otherwise progressing native chats. CLI caps remain configurable rather than secretly silently raised.

## 8. Lightweight tool orchestration and model-owned completion

Keep single-pass native tool selection. Continue `tool_search`/schema-on-demand; expose memory tools only to registries that intentionally support them. Do not expand the restricted `job_session.rs` registry. Keep exact argument validation, workspace sandbox, read/write distinctions and single-use approvals. Later, introduce explicit task/workspace-scoped grants to reduce repetitive prompts; never derive a grant from old memory, successful tool calls or assistant prose.

**Completion:** accept the model's tool-free public answer as the normal termination decision. Keep factual runtime correctness: no pretending a tool executed, no unacknowledged partial native call, no silent running subprocess as a finished result. Do not insert mandatory Rust-language task evaluation or a second LLM. Extract `Requirements` semantic inference from the completion path in a separate small refactor only after regression tests distinguish permission safety from task scoring. Optional future evaluator model/subagents attach to the model layer.

Tool output and historical text remain untrusted. Model-selected memory retrieval uses the existing authorized tool loop and never bypasses a denial.

## 9. Small staged delivery plan: every phase adds usability

| Milestone | User-visible gain | Main files | Acceptance / rollback gate |
|---|---|---|---|
| **M0 Baseline & audit** | Reproducible known-good checkpoint and explicit scope | docs, existing tests | `main` untouched; record baseline smoke results |
| **M1 Recall facade — started** | Model can discover `search_history` and `get_history_record` on ordinary chats | `src/memory.rs`, tools agent registry, `execution.rs`, `tests/agent_memory.rs` | Old exact text recovered after compaction; no approval, no cross-chat leakage |
| **M2 Durable indexed archive** | Fast recall after long sessions/restarts and historical tool outputs | `storage.rs`, `memory/archive.rs`, `index.rs`, `agent_chats.rs` | Crash/restart, legacy migration, FTS/exact matches, data integrity, deletion/export |
| **M3 Stable checkpoint epochs** | Much longer chat continuity and fewer repeated prefix invalidations | `context.rs`, `memory/checkpoint.rs`, `agentloop/context.rs`, provider budget | 100+ turn regression, pinned instructions, complete tool groups, bounded context |
| **M4 Cooperative working memory** | Model controls useful notes and proactive compaction | `tools/agent`, `memory/working.rs`, `execution.rs` | Correct notes/reference bounds; deterministic fallback for weak models |
| **M5 Input virtualization** | User pastes oversized docs/tasks without manual splitting | `memory/ingest.rs`, `runtime.rs`, `agent_chats.rs`, UI input handling | 30K input on 8K model; exact byte retrieval; full-coverage multi-pass |
| **M6 Output continuation** | Long reports and code responses continue seamlessly over multiple inferences | `memory/continuation.rs`, `execution.rs`, both provider adapters, Swift activity | Explicit length continuations, no call duplication/execution of partial JSON |
| **M7 Harness simplification & UX** | Less friction; optional export entire chat; model-owned stopping semantics | authority/inspection/verification boundaries, Swift conversation menu | Existing scope/approval/restart regressions pass; semantic audit no longer drives task |
| **M8 Hardware-aware preparation — last** | Automatic model/context advice based on resources | `core/models.rs`, provider adapters, Swift model picker, optional Hub/Ollama | Manual overrides; safe RAM/VRAM estimates; verified actual n_ctx; no silent downloads |

**Release policy:** one tightly scoped PR per milestone. Retain the previous working implementation until that milestone's targeted integration tests, full Rust tests, Swift test suite, and macOS native smoke checks pass. Never merge a feature solely on mocked-model tests.

### M1 caveat

The first patch uses a cheap conversation-local in-memory index reconstructed from already-saved original transcripts; it has **no new Cargo dependency** and is discoverable, but is **not** the final SQLite search index or crash-safe write-ahead archive. This is intentional progressive delivery, not a claim that the complete memory infrastructure is already finished.

## 10. Quality and performance gates

Baseline at the release: reported 230 Rust tests passed, seven opt-in ignored; 106 built Swift XCTest tests passed without rebuilding the native UI; 111 Job Apps Python tests passed. These are historical release reports, not tests rerun on the new branch.

Measure by model and allocation: prompt prefill latency, tokens/second, time to first visible token, peak resident/unified memory, prompt-cache reuse after 10/100/500 turns, context compaction count, full original recall accuracy, retrieval latency, tool-call success, malformed-call recovery, unexpected repeated effects, user approval interruptions, and disk growth per 1,000 turns.

Required fixtures:
- 8K, 16K, 32K, 65K contexts; both providers; thinking Off/Nominal/High where supported.
- Chat 100/500/1,000 turns; standing instruction at start and corrected midway; exact historical quote search.
- 30K/100K source input, UTF-8 and Markdown/code boundaries, first/middle/last exact-source queries.
- Multi-part output at a forced small generation limit, with no duplicated visible segment.
- Ongoing tool exchange at checkpoint boundary; refused and interrupted tools remain unexecuted.
- Cancellation, network loss, process restart and corrupt/partial disk write; zero permission or replay regressions.
- Native Swift UI scroll/copy/approval presentation and jobapps restricted-registry smoke.
- Real local-model acceptance distinct from deterministic tests; no benchmark claims before measurement.

## 11. Risks and decisions to record

- **Storage growth:** full original history is finite only by disk; implement retention/export/user deletion and quotas without silent loss.
- **Memory pressure:** avoid loading all archived text into RAM once FTS/sidecars exist; keep bounded LRU excerpts.
- **Semantic drift:** model-assisted notes may be wrong; keep source references, never replace originals.
- **Token estimation:** heuristics may underestimate; use provider token counts where possible and a conservative fallback.
- **Infinite continuation:** no global arbitrary cap for progressing tasks, but watchdogs must detect repeated identical failures and idle loops.
- **Compatibility:** support only compatible deployed model/chat formats; capability detection is better than pretending every model tool-calls reliably.
- **Security:** archived tool results and imported text are untrusted; model memory notes are advisory; no permission from historical events.
- **Licensing:** borrow architectural ideas from Unsloth, not code transplantation. Check licenses before any direct code import.

## 12. Definition of done for v0.5

A user can select a supported local model, paste source material exceeding one context window, interact for hundreds of turns, let the model recall exact earlier messages/tool observations, generate output spanning multiple requests, and resume after routine context pressure **without manually managing token limits**. The model, not Rust, decides its plan and semantic completion. The harness remains small, provider-independent, auditable and bounded in actual resource consumption. Real failures and insufficient hardware are communicated precisely rather than disguised as successes.
