## Architecture and changes from v0.4

The model chooses reasoning, plans, recall and semantic completion. Rust keeps
originals, finite inference budgets, authority, native execution and actual results.
There is one existing agent loop, no new agent/planner or memory service.

1. `memory.rs` now stores original records in per-conversation SQLite databases.
   One `rusqlite` dependency with bundled SQLite guarantees FTS5 availability across
   supported installations. FTS uses external content rather than another full text
   copy. SQL paging avoids loading all originals for each search/read. SQLite's
   transactions and full synchronization replace handwritten append recovery.
2. Existing draft JSONL imports once, transactionally, retaining the legacy file.
   Complete records before a torn final line remain retrievable. Malformed complete
   records roll back migration; corrupt databases are never replaced with empty ones.
3. Original user/assistant/tool content, tool IDs, structured calls and attachment
   metadata are retained. Private reasoning and recursively recalled results are
   excluded. Literal text that resembles a checkpoint is not discarded by prefix.
4. `get_history_record` supports complete chunk traversal and a paged `metadata`
   field. UTF-8 scalars, embedded NUL and large native arguments are tested. Search
   uses quoted literal terms/phrases, role filtering and bounded hit-centered snippets.
5. Oversized text receives a bounded manifest; its direct-input threshold shrinks
   with small allocations. Task contracts and instruction history retain the full
   original separately, including restrictions buried inside a large correction.
   Restricted custom registries never receive memory tools or virtualized inputs.
6. Context checkpoints use entry/target hysteresis, epoch numbers and explicit
   internal provenance. Recent operation facts are bounded; complete observations
   and effect/denial caches stay outside the prompt. Historical images may leave
   context while their original data remains archived. Prompt estimation avoids
   serializing a second full JSON copy just to count tokens.
7. `memory/continuation.rs` joins public segments, suppresses exact echoes and
   conservative suffix overlaps, and keeps streaming consistent with final text.
   No-progress stops preserve partial text. Empty final output after a length stop
   must recover once or report incomplete; it cannot silently complete the partial.
   Incomplete native argument batches are never executed or concatenated.
8. Completion is model-owned. Rust emits factual unresolved-operation and command
   status, without semantic final-answer retries. Changed tests explicitly verify
   unchanged files, absent approvals/effects, real failed results and no invented
   evidence. Different useful working notes are allowed; identical planning loops stop.
9. Whole-chat JSON/Markdown exports now include the archive as well as the compatible
   conversation/transcript. JSON embeds actual attachment bytes. Deletion removes
   SQLite/legacy sidecars; an open archive cannot continue reading a deleted chat.
10. The advisor displays physical/reclaimable memory, storage, installed metadata,
    actual reported context and llama.cpp measurements. New-load estimates are not
    presented as guaranteed fit for an already loaded model. It never requests router
    `/props?model=...`, which can autoload. Auto-detection skips empty llama.cpp catalogs.
11. CI checks committed formatting, Rust/Clippy, Swift and Job Apps. Runtime docs and
    the [architecture SVG](v0.5-architecture.svg) describe the actual candidate.

The incoming recall regression now passes through the real registry/loop and the
new index. The observed malformed-call recovery tests retain small-patch guidance
and precise bounded-recovery errors. Tests expecting a failed overall interaction
solely because a semantic requirement was inferred were replaced with factual
execution/authorization checks, not disabled or blindly loosened.

## Measurements (fixtures, not promises about model intelligence)

The deterministic storage/context fixture appends two original records per turn,
fits context after each turn, reconciles saved history at checkpoints, performs
100 searches per measurement and reopens the database at the end.

| Turns | Archive records | Elapsed | Mean indexed search | Database size | Context epochs |
|---:|---:|---:|---:|---:|---:|
| 100 | 200 | 188 ms | 205 µs | 299,008 B | 30 |
| 500 | 1,000 | 937 ms | 211 µs | 1,232,896 B | 164 |
| 1,000 | 2,000 | 1,885 ms | 181 µs | 2,420,736 B | 330 |

The isolated debug test executable peaked at **21,217,280 bytes resident memory**
(12,337,632-byte reported peak footprint), excluding all model weights and the UI.
Its final estimated prompt was 5,646/8,192 tokens. This is not a total-app RAM figure.

Further deterministic cases: 120 real file-read tools in one agent task; 20
public-output segments plus an echoed segment with per-character streaming; exact
whole-source traversal at 90,055 and 300,055 Unicode characters (44 and 147 chunks)
on an 8K scripted inference window. The large-input pair took 31.56 seconds in a
debug run. This exposes nontrivial harness/test overhead for many tiny retrieval
calls; it is not a model latency benchmark or proof of exhaustive model comprehension.

The real Ollama recall's final inference reported about 60 tokens/second, 1,920
prompt tokens, and 7 public generated tokens; total task time was 7.09 seconds.
The native edit/test/follow-up run completed its three stages in 30.23, 8.90 and
6.63 seconds. All three streamed; approvals numbered 1, 2 and 0 respectively.
These are single local runs, not cross-model performance rankings or TTFT benchmarks.

## Remaining limits and deliberate boundaries

- Model memory use and semantic understanding remain model-dependent. Source IDs and
  complete paging make exhaustive coverage possible; Rust does not claim to know
  whether a model actually understood every section or implemented every feature.
- FTS5 is lexical, not embeddings. Unicode offsets are scalars, not grapheme clusters.
  NUL-containing sources use per-record Rust paging because SQLite text functions
  stop at NUL. A very large single such record temporarily materializes in RAM.
- Echo suppression is deliberately conservative (exact prior-segment or 32+ character
  matching suffix, bounded lookbehind). Intentional repeated output can be ambiguous;
  no heuristic can universally infer whether repetition was intended.
- Hidden reasoning cannot be resumed verbatim. Timeout, cancellation and corrupt
  provider responses can leave partial work. Specific interruptions have bounded
  recovery; unrelated server failures remain errors.
- Originals are durable in ordinary saved chats. Standalone CLI/custom registries
  without a conversation binding do not gain a cross-process chat archive.
- Existing conversation JSON, full current-task audit and UI snapshots still consume
  memory/disk proportional to their histories. Removing the archive Vec is not a
  promise of constant total application memory. Very large export materializes its
  requested JSON/text explicitly. No automatic retention deletion is introduced.
- Existing HTTP body and per-tool/image/output bounds remain meaningful resource
  limits. Extremely small context windows may not fit schemas plus essential state;
  that is reported, not hidden by dropping restrictions.
- Existing version-one saved conversations are preserved. Old independent backups
  and exported files survive deleting a chat. Corrupt legacy complete records require
  explicit repair; a torn tail is retained, not fabricated as an original record.
- Hardware advice remains read-only and approximate. No automatic context fitting,
  model-quality ranking, download workflow or verified peak vision/KV fit is claimed.
- There was no available llama.cpp model: the router answered with an empty catalog.
  No live Gemma, vision-heavy or 1,000-turn LLM run was performed. Thinking-mode
  protocol regressions pass; the new real-model workflows were run with thinking off.
- No actual machine power-cut test or physical disk exhaustion was performed. SQL
  maximum-page exhaustion, corrupt files, torn migration and restart are automated.
- The package/app version remains 0.4 metadata until a separate release decision.
  Main and the Nominal tag are unchanged. CI on other operating systems remains a
  separate check from this machine's macOS results.

## Reproduce / build / rollback

```sh
git switch feat/v0.5-context-memory-foundation
cargo fmt --all -- --check
cargo test --locked --all-targets --no-fail-fast
cargo clippy --locked --all-targets -- -D warnings
python3 -B -m unittest discover -s jobapps/tests
python3 -B -m unittest discover -s macos/Tests/Restart
swift test --package-path macos
LORCA_BUILD_ONLY=1 bash macos/build.sh

# Real installed Ollama model; disposable files only.
LORCA_LIVE_MODEL=m2max-fast:latest cargo test --locked --test agent_live -- --ignored --nocapture --test-threads=1
LORCA_LIVE_MODEL=m2max-fast:latest cargo test --locked --test v05_live_memory -- --ignored --nocapture

# Unexecuted live llama.cpp gate: select a model already installed in your server.
LORCA_LIVE_PROVIDER=llama_cpp LORCA_LIVE_HOST=http://127.0.0.1:9931 \
LORCA_LIVE_MODEL='<installed llama.cpp model ID>' \
cargo test --locked --test v05_live_memory -- --ignored --nocapture

python3 macos/Acceptance/run.py --selection --skip-build --model m2max-fast:latest --effort off \
  --sdk /Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk
python3 macos/Acceptance/run.py --v05 --skip-build --model m2max-fast:latest --effort off \
  --sdk /Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk
cargo test --locked --lib thousand_turn_archive_and_context_benchmark -- --nocapture
```

The built review app is `macos/build/lorca.app` in the isolated worktree
`/private/tmp/lorca-v05`. Build-only mode never installs/restarts production.
For a normal clean restart after review, use the project's existing rebuild command
from this branch. Avoid running two different builds against the same live data root.

Migration is additive: SQLite files appear in `memory/<conversation-UUID>.sqlite3`.
Existing JSON and draft JSONL remain. Before reverting to v0.4, export/back up the
chat and memory directory. v0.4 can read its existing conversation JSON but does
not read v0.5-only archived observations; rollback does not automatically convert
those back to the old format. Do not delete originals to obtain a clean downgrade.

## Complexity review and evidence locations

`rusqlite` plus bundled SQLite is the only new runtime dependency. The new public
continuation helper is approximately 100 lines including tests. Storage/retrieval
stays behind `HistoryIndex`; tools and the four-pillar gateway remain unchanged in
shape. There are no subagents, embeddings, extra model calls for routing, memory
workers or Job Apps changes. Some inherited English restriction parsing, inspection
helpers and duplicated legacy UI/audit storage remain; removing them blindly would
risk permissions or saved-chat compatibility and is not part of this candidate.
