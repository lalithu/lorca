## Architecture and limits

The existing two-stage model flow, scheduler and approval lifecycle remain in place. The raw instruction and trusted continuation history ground inspection requirements. Model proposals can label inspection subjects, but they do not establish file identities or permissions. Execution records tool results in the task transcript. Before assessing inspection evidence, Rust matches it to the preceding tool call and checks workspace and filesystem generation through the existing capability. The same inspection assessment feeds normal completion, the verification event and the early finalization check. No dependencies or model settings were changed.

The generation identity uses Unix filesystem device, inode, length, and nanosecond modification/change times. Evidence is revalidated before use, with no atomic snapshot of a concurrently changing tree. Directory enumeration deliberately fails closed at the existing listing limit. Historical unversioned inspection evidence is re-read rather than reused. Provenance records the trusted instruction indices. The repair does not implement a complete persistent ledger of every superseded requirement and its evidence, and it does not support unrestricted natural-language range and scope expressions.
